# lab/ — 検証用のコード置き場

本実装の前に「成立するか」を確かめるための、使い捨て前提のコード。

```
lab/typst-browser/   ブラウザで typst.ts を動かし、初回ロードと編集の応答を測る
```

## 前提（shibadocs が何をするものか）

Markdown とドキュメントサイトを、**Typst 経由で和文の PDF にする**ツール。
ブラウザ印刷でも LaTeX でもなく、組版エンジンに Typst を使う。

作る順序:

```
1. PDF（単一ファイル + CLI + Docusaurus プラグイン）
2. ドキュメントサイト全体 → 1冊の PDF
3. SPA（ブラウザ完結のエディタ + プレビュー）
4. Excel
```

**1 と 2 は Node で動く**ので、ブラウザ側の検証が通らなくても成立する。
`lab/typst-browser` が確かめているのは **3（SPA）が成立するか**で、
初回ロードが遅すぎるなら SPA を後回しにして Excel を先に作る、という分岐だった。

## 製品コードとの関係

**lab/ のコードは製品に持ち込まない。** 出すのは数字と判断だけ。

| | |
|---|---|
| 置き場 | pnpm workspace の一員（`lab/*`）。ただし `private: true` で publish しない |
| 依存 | 製品側（`packages/*`）から `@shibadocs-lab/*` を参照しない |
| 寿命 | 判断が終わったら消してよい。残すのは結果の md と `results/*.json` |

## 結果

各ディレクトリの `RESULT.md`。数字の裏付けは `results/*.json`。
